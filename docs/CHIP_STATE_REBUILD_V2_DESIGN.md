# CYQ-GAME 筹码状态重建 v2

状态：`DESIGN_FROZEN_FOR_TARGETED_IMPLEMENTATION`
适用范围：筹码内核、每日快照、公司行动/流通股本衔接、策略锚点
禁止事项：本设计的 G0–G4 未通过前，不得恢复全市场多年重建或回测

## 1. 先纠正一个根本误区

每日价格—筹码直方图只能回答：

> 当前模型认为筹码分布在哪些成本位置？

它不能回答：

> 吸筹锚点当天的那批筹码，今天还剩多少？

即使锚点和今天的直方图完全相同，锚点筹码也可能已经全部卖出，再由新成交筹码填回同一价格桶。因此：

- 当前直方图在锚点价格带内的质量称为 `support_occupancy`；
- 锚点原始筹码经过逐日卖出模型后仍存续的比例称为 `origin_retention`；
- 前者是结构支撑占用，后者才是模型意义下的底仓保留；
- 两者都只是持仓成本模型的结果，不能声称识别了真实庄家账户。

旧实现的 `base_retention(current_histogram, anchor_band)` 实际计算的是
`support_occupancy`，把它命名为底仓保留会产生系统性误判。本次重建不再修补该公式，而是增加独立的原始筹码存续链。

## 2. 最小且不可混合的五层

1. **PIT 原始事实**：未复权日线/分钟线、成交量、流通股本、交易状态、公司行动和市场规则。
2. **筹码迁移模型**：声明卖出假设，产生每日成交分布和旧筹码存续映射。
3. **不可变快照与迁移日志**：保存 `PRE`、`POST` 状态及从前一状态到后一状态的可重放变化。
4. **策略锚点及原始筹码追踪器**：只引用快照和迁移日志，不复制、修改或重新解释底层状态。
5. **策略生命周期**：决定何时提出候选吸筹、确认锚点、突破、回踩、派发或破坏。

筹码层不知道 `ACCUMULATING`、参数阈值或未来标签；策略层不能改写历史筹码状态。

## 3. 三个核心对象

### 3.1 每日边际状态 `ChipSnapshotV2`

每个交易日必须有清晰的事件次序：

```text
上一日 POST
  -> 当日开盘前已生效且当时可知的公司行动/供给变化
  -> 当日 PRE
  -> 使用 PRE 计算 CYQK_pre
  -> 当日成交迁移
  -> 当日 POST
```

`PRE` 和 `POST` 都是不可变、带内容和输入版本的快照。快照至少包含：

- 稳定网格上的价格×年龄稀疏筹码状态；
- 交易取得成本和现金分配后的经济盈亏平衡成本；
- 已知成本流通筹码、未知成本流通筹码、潜在供给和流通股本；
- 初始化先验仍存续的质量；
- `decision_at`、`effective_at`、`available_at`、`snapshot_id`；
- 模型版本、网格版本、输入快照 ID、PIT 等级和 `hard_valid`；
- 守恒残差、量化误差和质量原因码。

快照是全市场共享事实，不随策略参数变化。

### 3.2 存续映射 `OriginSurvivalTransition`

每天除边际状态外，还要保存一个旧状态到新状态的稀疏存续映射：

```text
(source_cell, destination_cell, retained_fraction)
```

同一源单元所有弧的 `retained_fraction` 之和不得大于 1。差额表示该源筹码在当日模型中卖出。新成交分布 `q_t` 进入边际状态，但永远不进入旧锚点的存续映射。

若源筹码为 `u_{t-1,i}`，则锚点原始筹码只按下式推进：

```text
u_{t,j} = sum_i(u_{t-1,i} * R_t[i,j])
origin_retention_t = sum_j(u_{t,j}) / root_origin_units
```

而每日边际筹码为：

```text
S_post_t = R_t(S_pre_t) + Q_t
```

这里 `Q_t` 不得出现在 `u_t` 中。这一隔离保证同价位新换手不能伪造底仓保留。

存续映射允许一个源单元映射到多个目标单元，以支持稳定网格重投影、年龄推进和公司行动，不能再用“最近桶硬搬运”隐藏一阶矩误差。

### 3.3 策略锚点 `AnchorCandidateRef` / `LifecycleAnchorRef`

锚点不复制直方图，只引用不可变快照并创建一个原始筹码追踪器：

- 候选吸筹出现时，立刻因果地创建 `AnchorCandidateRef`；
- 候选成立需要固定的连续/`K of N` 证据，确认日才创建 ROOT 锚点；
- ROOT 可以引用此前已经冻结的候选快照，但确认日期不得回填为候选开始日；
- 后续支撑区受控上移时创建新的 SUPPORT 子锚点；
- ROOT 永不覆盖，子锚点记录 `root_anchor_id`、`parent_anchor_id` 和来源快照；
- ROOT 的原始筹码保留率和最新 SUPPORT 的结构支撑分别报告，不互相替代。

“洗筹几个月”由生命周期观察期限和子锚点规则处理，不通过滚动 20 日基准冒充长期底仓。

## 4. 稳定网格和年龄状态

旧实现会在价格超出区间时重建动态网格，并把旧质量搬到最近桶。这会导致桶身份变化、价格矩漂移和锚点无法严格重放。

v2 使用版本化的全局整数对数桶：

```text
bucket_id = round(log(price / reference_price) / log(1 + step_pct))
```

- `reference_price`、`step_pct` 和取整规则属于 `grid_version`；
- 年龄为单独维度，状态单元 ID 由 `(bucket_id, age_bucket)` 唯一构成；
- 必须重投影时使用相邻桶线性分配，显式保存映射和一阶矩误差；
- 不允许通过重新归一化使质量和看起来等于 1。

网格精度属于模型版本，不能在参数搜索时变化。

## 5. 取得成本与经济成本必须分开

一个状态单元保存两套坐标：

- `acquisition_cost`：该筹码模型中的交易取得成本，用于筹码峰、结构支撑和成交迁移；
- `economic_break_even`：考虑已收到现金分配后的经济盈亏平衡成本。

处理规则：

- 现金分红：未复权 OHLC 和取得成本不变，只降低经济盈亏平衡成本；
- 拆股/送转：两套每股成本按比例下降，已知筹码股数和流通股本按比例增加；锚点追踪的无量纲原始所有权单位不增加，保留率不变；
- 配股/增发：在 PIT 生效时间按已知发行价格加入新的已知成本供给；
- 解禁但来源成本未知：进入 `unknown_cost_shares`，不得猜测塞入当天成交分布；
- 回购注销：若无法确定从哪类供给扣除，严格状态失败；
- 公司行动无法完整解释股本桥接时，`hard_valid=false`，不得用复权价格平滑掩盖。

## 6. 绝对股数守恒，不只保存归一化概率

每日状态按绝对流通股数记账：

```text
known_cost_shares + unknown_cost_shares = free_float_shares
```

潜在未流通供给单列，不进入等式左侧。成交迁移只改变已知筹码的成本/年龄分布，不创造或销毁流通股数。数值容差只用于浮点比较，任何残差都要保存并超限失败，绝不调用归一化修正。

若未知成本流通股占比超过模型允许值：

- 可以保留 `B_RESEARCH_ONLY` 状态并披露不确定性；
- 必须令严格 `hard_valid=false`；
- 策略不能把未知供给解释成底仓或新主峰。

## 7. 初始化不是事实，而是可消退先验

首日用当日成交分布初始化，只是一个先验，不能称为真实存量持仓。状态必须追踪 `prior_origin_shares`，并像普通锚点一样随卖出模型逐日衰减。

锚点可用性不再由固定“预热 20 日”决定，而由：

- 初始化先验存续占比低于阈值；
- 累计有效换手达到阈值；
- 流通股本和公司行动链连续；
- 多个合理卖出模型对主要结构结论没有严重冲突。

不满足时仍可保存每日状态，但不能产生严格新风险。

## 8. 分钟数据能解决什么、不能解决什么

1 分钟线改善的是当日成交价格分布 `q_t`、价格冲击、VWAP 和尾盘行为。它不能识别是哪个历史成本/年龄群体卖出了筹码。

卖出危险率仍是模型假设，例如年龄、盈利程度和套牢程度的函数。因此 v2 至少保存：

- 使用的卖出模型和参数版本；
- 每个源单元的存续映射；
- 均匀换手模型与年龄/盈亏危险率模型之间的分歧。

如果信号只在某一个激进假设下成立，而合理备选模型不成立，应标记 `AMBIGUOUS_MODEL` 或 `NO_TRADE`。不能用未来收益反向挑选一个“看起来最真实”的筹码模型。

## 9. 生命周期证据的正确语义

策略每天同时读取以下独立证据：

- `root_origin_retention`：ROOT 原始筹码模型存续比例；
- `support_origin_retention`：最新 SUPPORT 原始筹码存续比例；
- `root_support_occupancy`：当前边际筹码仍在 ROOT 价格结构中的占用；
- `cost_migration`：p50、均值和主峰相对 ROOT/SUPPORT 的迁移；
- `concentration_change`：带宽、集中度和峰分裂；
- `distribution_evidence`：原始筹码流失、高位新成本扩张、高换手低冲击的连续证据；
- `model_disagreement`：合理卖出模型间差异。

受控上移只创建 SUPPORT 子锚点，条件至少包括：ROOT 尚未实质流失、成本缓慢上移、集中度未恶化、无峰分裂和无结构破坏。它不能把已经流失的 ROOT 历史“洗白”。

## 10. 可重放存储与加速

不为 81 组参数重复计算筹码：

- 每日保存轻量标量特征和稀疏边际状态；
- 每日保存一次存续映射及成交分布摘要；
- 定期保存完整价格×年龄检查点，其余日期保存增量；
- 锚点追踪从最近检查点重放，并按
  `(symbol, root_snapshot_id, model_version)` 缓存；
- 所有策略参数共享每日快照和锚点追踪结果，但维护各自独立生命周期状态。

并行单位是相互独立的股票桶；单只股票内部按日期有序推进。合并输出按股票和日期稳定排序，保证不同核数得到相同哈希。

## 11. 实现与验收门禁

### G0：契约

- PRE/POST、双成本、绝对股数、存续映射、候选/ROOT/SUPPORT 均有不可变类型；
- PIT 时间和供给守恒在构造时失败关闭；
- 同价位新成交不能进入锚点追踪器。

### G1：纯合成事件

- 边际直方图不变但旧筹码卖出 75% 时，`support_occupancy` 可保持 100%，`origin_retention` 必须为 25%；
- 停牌日无成交，锚点存续率为 100%；
- 现金分红只改变经济成本；
- 拆股后绝对股数桥接、成本坐标和锚点保留率正确；
- 未知解禁、错误股本桥接、未来 `available_at` 都失败关闭；
- 从检查点重放与连续逐日计算逐单元一致。

### G2：引擎适配

- 现有均匀/群组引擎输出边际状态的同时输出存续映射；
- 删除核心迁移中的 `initial_base_band`；
- `CYQK_pre` 只读取公司行动后的 PRE，成交迁移只影响 POST；
- 旧 `base_retention` 政名为 `support_occupancy`，不得进入正式底仓证据。

### G3：单股短样本

选正常交易、停牌、现金分红、送转/拆股和流通股本变化窗口，各运行一个股票数周：

- 每日核对 PIT、守恒、PRE/POST 和重放；
- 与分钟成交量聚合交叉核对 `q_t`；
- 比较不同模型并披露分歧；
- 不运行参数搜索和回测。

### G4：性能门禁

- 单只股票结果在 1 核与多核完全一致；
- 同一快照和锚点只计算一次；
- 先测 20 股一周，再测 20 股一年；
- 若存在逐参数重建、逐行 DataFrame 循环或重复 Parquet 扫描，先优化，不得扩大范围。

只有 G0–G4 全部通过，才允许生成全市场 2018–2026 筹码状态。生成完成并通过覆盖与质量审计后，才恢复策略研究；回测仍在策略和软件门禁之后。

## 12. 明确不接受的替代方案

- 用当前直方图与旧价格带重合度冒充原始底仓保留；
- 每 20 日重新定义“底仓”，导致派发历史被覆盖；
- 突破后用未来信息回头选择最漂亮的吸筹起点；
- 现金分红直接平移交易取得成本；
- 用归一化掩盖流通股本、公司行动或迁移质量错误；
- 把分钟线存在解释为持有人身份可知；
- 为每组策略参数重新运行筹码重建；
- 在短样本守恒与重放尚未通过时启动全量任务。
