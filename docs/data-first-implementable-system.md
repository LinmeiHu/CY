# CYQ-GAME 数据可实现版系统设计

## 结论

系统只实现一条最短可验证链路：冻结数据 -> PIT 规范化 -> 审计与 `hard_valid` -> 筹码/市场/板块状态 -> 单一策略决策 -> 因果成交仿真。QMT 是行情、分钟/Tick、历史流通股本、停牌状态和实时可成交性的主源；CNINFO 只补最终公司行动及公告时间，交易规则由版本化规则表派生。2018、2019 年分钟数据是正式资产，不应放弃，但首轮只实现日线研究链路。

当前全局状态是：CY-003 已形成 2018–2026 日线 PIT-B 因果研究表，五类审计通过，精确绑定 R2 manifest 后允许真实研究回测。缺少 PIT 行业、历史流通股本、公司行动、交易状态或规则的行保持 `hard_valid=false` 并禁止新增风险；严格 PIT-A 归档仍延期。

## 由现有数据决定的能力边界

| 能力 | 当前结论 | 设计处理 |
|---|---|---|
| 未复权日线与指数环境 | 保留，条件可用 | 作为价格事实核心，补记录级 `available_at/snapshot_id` 后进入 PIT 仓 |
| 2000–2026 未复权 1 分钟行情 | 保留，条件可用 | 2020 年前分钟策略能力保留；1 分钟因果聚合为 5 分钟，不使用未来窗口 |
| 筹码成本分布与迁移 | 保留为估计器 | 使用统一未复权坐标；公司行动除权日重基；质量未知时不生成严格状态 |
| T0–T9、市场/板块状态 | 保留为多标签潜变量 | 状态不是订单；板块特征必须 PIT 成员关系和 leave-one-out |
| 证券池、行业成员、流通股本 | PIT-B 已接入 | 行业日表、注册证券池和 QMT Capital 均进入 CY-003；缺失即 `hard_valid=false` |
| 公司行动、市场规则、交易日历 | PIT-B 已接入 | CNINFO 最终行动事实与版本化规则已进入 CY-003；公告时间与生效时间分离 |
| 基本面/宏观解释 | 延期 | 不属于首个可回测版本；以后只能接 publication-aware 快照 |
| 盘口队列、逐笔委托成交模型 | 延期 | 当前没有历史 L2；分钟成交模型不得宣称队列位置精度 |
| 真实庄家账户和意图识别 | 放弃 | 参与者只能是可证伪的潜在假设，不能声称识别真实账户 |
| 当前快照历史回填 | 禁止 | 仅可用于发现、交叉核验，不能进入历史因果状态 |
| HMM、参与者生态和实盘交易 | 延期 | 不属于首个可回测版本；不阻塞数据主线 |

## 目标架构

```text
数据资产注册表（允许发现什么）
        |
冻结输入快照（本次到底用了什么、覆盖何时、哈希为何）
        |
规范化适配器（原始未复权事实 + available_at + snapshot_id）
        |
五类数据审计 + 跨表 hard_valid 连接
        |
PIT 仓（身份不可重绑定；只按 decision_at 查询）
        |
筹码成本状态/CYQK_pre -- 公司行动重基与质量守恒
        |
市场 + PIT板块LOO + 必需的 T0-T9 多标签 + 独立风险状态
        |
单一 StrategyFamily + 最小完整 EdgeCard
        |
Q(action) 与 NO_TRADE 比较（费率、滑点、冲击、封板退出风险）
        |
版本化 TradePlan；信号 bar t 最早在下一可交易 bar 成交
```

解释层不能回写价格、筹码或数据质量事实。风险与数据有效性是独立覆盖层；高质量价格数据不能替代未知流通股本、公司行动、交易状态或市场规则。

## 唯一实现主线

使用 QD-001/QD-002/QD-003/QD-004 的未复权事实。日线用于长周期筹码迁移与市场环境，1 分钟数据保留 2020 年前后的盘内结构；5 分钟只能由已闭合的 1 分钟窗口因果聚合。日线和分钟线在字段、单位、交易日与价格坐标未通过跨表审计前分别建模，不强行混合。

这条通道只有在逐日证券身份、流通股本、公司行动、交易状态和市场规则都可得时才可产生严格筹码状态。流通股本决定换手质量，公司行动决定成本坐标，二者不能用最新值替代历史值。

每个候选状态只增加两个必要门禁：`DataQuality` 判断输入是否完整一致，`Observability` 判断现有数据是否足以区分交易解释。任一必需数据未知、解释不可辨识、风险覆盖或不可成交，都降为 `NO_TRADE`。

## 四类必需数据与当前资产

1. 价格与交易状态：QD-001 至 QD-006。物理核心存在；QD-004 包含 2020 年前分钟数据。
2. 证券身份、行业成员与流通股本：QD-007 至 QD-009。QD-008 已按披露日接入；QD-009 已冻结并按生效日与公告日双重 as-of 接入；证券池从已注册日数据派生。
3. 公司行动、交易日历与市场规则：QD-010、QD-012、QD-013。当前快照只可核验，不可冒充历史公告快照。
4. 市场环境：QD-003。基本面 QD-011 延期，不阻塞首个版本；板块 alpha 默认关闭，但 PIT 行业缺失仍触发 `hard_valid=false`。

全市场首个 PIT-B 版本使用守恒的 `uniform` 固定网格筹码引擎；`cohort` 年龄队列实现保留，只用于小样本鲁棒性验证。该取舍不改变筹码成本状态的定义，也不放松 `CYQK_pre`、公司行动重基和质量门禁。

`CY-OUT-001` 等生成物永远是输出而非输入。QD-014 的前复权派生因子只用于 QA；它不能替代同一未复权坐标上的因果计算。

## 实施顺序与门禁

| 阶段 | 交付物 | 进入下一阶段的门禁 |
|---|---|---|
| D0 资产真相 | 注册表、能力/缺口矩阵 | 位置、来源、覆盖和用途明确 |
| D1 冻结输入 | 输入快照清单、目录 inventory、哈希 | 路径和哈希可重验；范围固定 |
| D2 规范化 | 四类适配器、字段/单位契约、记录血缘 | 每条记录有来源、`available_at`、`snapshot_id` |
| D3 单表审计 | 覆盖、重复、时间穿越、一致性证据 | 审计可重复且 PASS |
| D4 跨表有效性 | `(symbol, decision_at)` 级 `hard_valid` 与原因码 | 公司行动/流通股本/状态/规则均闭环 |
| S 状态工程 | 筹码守恒、CYQK_pre、市场/板块/T0–T9/风险状态 | 无同 bar、无平滑未来、PIT LOO |
| Q 决策工程 | EdgeCard、NO_TRADE、成本后 Q、分数 Kelly | 概率仅用 OOS 校准；风险可覆盖 |
| V1 短验证 | 3–6 个月开发样本 | 机制、守恒、执行语义通过 |
| V2 局部回归 | 1–2 年多市场环境 | 稳健性与失败场景通过 |
| V3 最终验收 | 2020–2026 冻结全量 | 所有前置门禁通过后仅运行一次 |
| V4 严格 PIT | A 级归档快照全量 | `strict_archival_pit_ready=true` |

软件层已经实现 D1/D2 的冻结与规范化机制、D3 五类确定性审计器、D4 六类必需数据的 PIT 截止时点连接，以及“D4 不通过就不生成严格股票状态”的最小门禁。QD-001 至 QD-003 的实际文件和 QD-004 的 2018–2026 目标范围已经完成逐文件内容 inventory；四个适配器均已读取真实单标的样本。准备快照为 [`CYQ-PREP-2018-2026-20260820.json`](../data/input_snapshots/CYQ-PREP-2018-2026-20260820.json)。

D1–D4 已在 CY-003 PIT-B 日线表闭环：9,421,907 行中 9,065,778 行 `hard_valid=true`，其余 356,129 行保留原因码并失败关闭；覆盖、重复、时间穿越、一致性和跨表审计均 PASS。`free_causal_research_ready` 与 `backtest_authorized` 已仅对冻结的 R2 manifest 放行，`strict_archival_pit_ready=false`。

V1–V3 也已按门禁顺序完成，并对每个阶段执行确定性重放。最终全市场 2020–2026 运行工程验收 PASS、策略经济晋级 FAIL；详细命令、退出码、指标和产物哈希见 [`pit-b-final-validation.md`](pit-b-final-validation.md)。V4 严格 PIT-A 是后续独立升级，不再反向阻塞本次 PIT-B 因果研究结论。

## 当前实现重点

- 数据资产注册表是唯一白名单；路径、文件哈希或目录 inventory 不一致立即失败。
- 每次操作必须携带输入快照授权；授权固定用途、日期范围和真实输入身份。
- PIT 仓首次摄取前绑定输入身份，完成后不可改绑；未完成或不匹配的仓不能生成策略状态。
- 软件测试、数据准备和真实研究严格分域；QA 数据不能驱动策略状态。
- 当前执行顺序固定为：一标的 3–6 个月 -> 10 标的 1–2 年 -> 全市场短样本 -> 2020–2026 最终全量；任何前置门禁失败都不得跳级。不扩展财务/HMM/实盘或复杂板块 alpha。

只有注册表发现了新数据并完成定点核验后，才允许追加资产或升级状态；不得因代码“需要某字段”而假定数据已经存在。
